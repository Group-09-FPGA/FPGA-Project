Hardware-Accelerated Limit Order Book (LOB) & Matching Engine

Deterministic Sub-Microsecond Financial Matching with RV32IM Coprocessor & Real-Time Visualization

Core Problem

Software order matching suffers severe microsecond latency jitter and memory cache misses during high-frequency market burst traffic.

System Description

We implement a pure-hardware order matching core on the Digilent Nexys A7 FPGA that manages limit order tracking, price-time priority matching, and Best Bid & Offer (BBO) computation deterministically in ≤ 4 clock cycles, paired with an out-of-band RV32IM RISC-V coprocessor for telemetry, live 640x480 VGA depth rendering, and 921.6 kbaud UART logging.

Commitment (Guaranteed)

  • ✓ RV32IM softcore with wait-state system bus & hardware MUL/DIV (Already physically validated on Nexys A7).
  • ✓ Hardware LOB core tracking 4K orders with deterministic 4-cycle insertion/cancellation and BBO updates.

Goal (Target Submission)

  • ✓ Hardware matching engine executing incoming crosses in ≤ 6 cycles with Level-2 depth tracking.
  • ✓ Live 640x480 VGA display showing dynamic bid/ask depth ladders + high-speed UART telemetry (921.6 kbaud).

Verification Plan & Edge Cases

1. Module-Level Unit Testing
  • Standalone testbench for every extracted block (tb_alu, tb_hazard, tb_decoder).
  • Multi-cycle timing verification: Skid-buffer holds valid opcode without pipeline drops.
2. Exhaustive Hardware Edge-Case Suite
  • Signed/Unsigned Multiplications: MUL, MULH, MULHSU, MULHU.
  • Division by Zero: div x, x, 0 → -1; rem x, x, 0 → dividend.
  • Signed Division Overflow: -2^31 / -1 → -2^31 with remainder 0.
  • LOB Book Underflow: Empty book checks (Ask=0xFFFFFFFF, Bid=0x0), slot hash collisions.
3. Processor-Level Validation (C Programs & Board Execution)
  • 100% cycle-by-cycle trace match across 5 baseline benchmarks: addition, fibo, negative, sort, xor.
  • Hardware assembly program (code_rv32m.s) executed on Nexys A7: Confirmed pass sentinel 0xCAFE.
Quantifiable Design Goals: Deterministic Latency: ≤ 4 cyc (Insert/Cancel), ≤ 6 cyc (Match) Throughput: > 16.6 Mops/s @ 100MHz Resource Cap: < 25% LUTs, < 20% BRAMs Timing Slack: WNS > 0.40 ns

Hardware FPGA Demo Plan & Engineering Challenges

Live FPGA Demonstration Flow: Input → Processing → Output

STAGE 1: INPUT
Pre-Recorded ITCH 5.0 / CPU Stream

Host transmits pre-recorded NASDAQ TotalView-ITCH packet stream via Ethernet/UART, or CPU executes synthetic order generator injecting 1,000 orders/sec into MMIO FIFO.

STAGE 2: PROCESSING
Hardware LOB Core & Matching

Hardware LOB processes order insertions, cancellations, and executes crossing trades in ≤ 4–6 cycles. Maintains BBO spread and updates dual-port frame BRAM in real time.

STAGE 3: OUTPUT (VISIBLE)
3 Live Board Observability Interfaces

1. VGA Monitor: Dynamic green (bids) and red (asks) depth bars.
2. 7-Segment Display: Live BBO Spread & Best Bid price.
3. UART Terminal: Microsecond timestamps & trade fill receipts.

Challenge 1: System Bus Wait-States & Multi-Cycle Stalls

Issue: Variable MMIO latency could cause pipeline deadlocks if stores and loads overlap with M-extension operations.
Mitigation: Strict 4-state non-preemptive bus arbiter freezes pipeline registers with skid buffers until slave signals rsp_valid.

Challenge 2: Atomic Multi-Word Reads & Tearing

Issue: Reading 64-bit timestamps and quantities sequentially risks reading inconsistent high/low halves during live ticks.
Mitigation: Hardware shadow registers with latch-on-read-low semantics ensure CPU snapshots remain atomic.

Challenge 3: Signed/Unsigned Arithmetic & Book Underflow

Issue: Partial cancellations or division overflows could wrap shares negative or corrupt pricing.
Mitigation: Complete RISC-V edge case compliance + hardware saturation logic asserting sticky error flags in LOB_ERROR_FLAGS.

Challenge 4: Multi-Clock Domain Crossing (CDC) & Timing Closure

Issue: Interfacing 100 MHz Core, 50 MHz Ethernet, and 25.175 MHz VGA domains without metastability.
Mitigation: Dual-port BRAMs serve as native CDC raster buffers; asynchronous Gray-code FIFOs pass events; timing fully closed.
