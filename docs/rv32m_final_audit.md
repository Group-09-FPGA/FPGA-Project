## 3. RV32M Functional Correctness Findings

### 3.1 Decode and Architectural Behavior
- **Opcode & Funct Decode:**
  - Opcode: `7'b0110011` (`ARITHR`)
  - Funct7: `7'b0000001`
  - In `rtl/cpu/core/decoder.v`: `m_op = (opcode == ARITHR) && (funct7 == 7'b0000001)`.
  - Non-M instructions with `funct7 == 7'b0000000` or `7'b0100000` are correctly routed to `alu = 1`. Any invalid `funct7` triggers `illegal_inst = 1'b1`.
- **Destination & Memory Gating:**
  - `mem_write = (opcode == STORE)` $\rightarrow 0$ for all M instructions.
  - `mem_to_reg = (opcode == LOAD)` $\rightarrow 0$ for all M instructions.
  - In `cpu_core.v`: `wb_req` and `ex_req` are strictly zero during M instructions, guaranteeing **zero unintended memory or peripheral transactions**.
- **Register `x0` Invariance:**
  - In `rtl/cpu/core/reg_file.v`, writeback is gated with `if (write_enable && write_addr != 5'd0)`.
  - Verified in `tb_rv32m_pipeline.v`: both `mul x0, x1, x2` and `div x0, x6, x2` execute, stall the pipeline normally, and commit without altering `x0` (`read_data1 == 0x00000000`).

### 3.2 Multiplication Microarchitecture & Verification
- **Operand Width & Sign Extension:**
  - Signed operand extension: `wire sign_a = (funct3 == F3_MULH) || (funct3 == F3_MULHSU);` and `wire sign_b = (funct3 == F3_MULH);`.
  - `ext_a = sign_a ? {op1[31], op1} : {1'b0, op1};` (33-bit signed).
  - `ext_b = sign_b ? {op2[31], op2} : {1'b0, op2};` (33-bit signed).
  - Intermediate product: `reg signed [65:0] mult_prod_r2 = mult_reg_a * mult_reg_b;`.
- **Result Truncation:**
  - `MUL`: lower 32 bits `mult_prod_r2[31:0]`.
  - `MULH`, `MULHSU`, `MULHU`: upper 32 bits `mult_prod_r2[63:32]`.
- **Mathematical Soundness:**
  - By sign-extending operands to 33 bits, both signed and unsigned 32-bit values map into non-negative or two's complement representations within the same 33-bit signed domain.
  - The $33 \times 33$ signed multiplier naturally accommodates:
    - Signed $\times$ Signed (`MULH`): bit 63 is the product sign bit, bits [63:32] form the high 32 bits.
    - Signed $\times$ Unsigned (`MULHSU`): operand B has MSB 0, representing non-negative magnitude up to $2^{32}-1$.
    - Unsigned $\times$ Unsigned (`MULHU`): both operands have MSB 0.
- **Reference Model Verification:**
  - Verified across 236 unit tests and 160 randomized test vectors comparing against independent 64-bit Verilog arithmetic (`$signed({{32{a[31]}}, a}) * $signed({{32{b[31]}}, b})`). Zero mismatches.

### 3.3 Division and Remainder Microarchitecture & Edge Cases
- **Restoring Recurrence:**
  - Implements 32 shift-and-subtract recurrence iterations across `div_cnt` 0..30, with iteration 31 and sign correction performed combinatorially during the transition to `STATE_DONE`.
- **Required Architectural Corner Cases (All Verified):**
  - Division by zero: `DIV(x, 0) = 0xFFFFFFFF`, `DIVU(x, 0) = 0xFFFFFFFF`, `REM(x, 0) = x`, `REMU(x, 0) = x`.
  - Signed overflow: `DIV(0x80000000, 0xFFFFFFFF) = 0x80000000`, `REM(0x80000000, 0xFFFFFFFF) = 0x00000000`.
  - Signed truncation towards zero: verified for $(+7/+2), (-7/+2), (+7/-2), (-7/-2)$. Remainder sign strictly matches dividend sign.

## 4. Operation Latency & Pipeline Accounting

### 4.1 Counting Conventions
1. **Elapsed Clock Periods** ($T_{\text{done}} - T_{\text{start}}$):
   - Multiplier: **2 clock periods** (20 ns @ 100 MHz).
   - Divider: **32 clock periods** (320 ns @ 100 MHz).
2. **Active Clock Edges** (From sampling edge of `start` up to and including rising edge where `done` asserts):
   - Multiplier: **3 clock edges** (Edge 1: Capture Stage 1; Edge 2: Capture Stage 2 product; Edge 3: Capture Stage 3 result & assert `done`).
   - Divider: **33 clock edges** (Edge 1: Capture init; Edges 2..32: Iterations 0..30; Edge 33: Iteration 31 + correction + assert `done`).
3. **EX Stage Residence in CPU Core:**
   - Multiplier: 3 cycles.
   - Divider: 33 cycles (1 launch cycle + 32 stall cycles). Result advances from EX to WB on cycle 34.

### 4.2 Pipeline Control Audit in `cpu_core.v`
- **Exact-Once Execution:** Multi-cycle launch is protected by `m_start = ex_m && !m_busy && !m_done && !m_started && !branch_stall`. The registered pulse `m_started` prevents re-firing while stalled in EX.
- **Writeback Validity:** Register write enable is gated by `!stall_pipeline && !wb_stall && wb_reg_write`. Because `m_stalling` holds `stall_pipeline = 1`, no intermediate or invalid results are written to the register file.
- **Branch Misprediction Flush:** Gated by `!branch_stall`. When a branch mispredicts, `branch_stall` asserts, forcing `m_start = 0`, `m_stalling = 0`, inserting bubbles and discarding any uncommitted M instruction.
- **External Stall Holding:** If `stall_pipeline` is asserted externally on the completion cycle, `rv32m_unit` holds `done` high and `result_reg` valid indefinitely in `STATE_DONE` until `!stall_pipeline`.

## 5. Instruction-Fetch Skid-Buffer & Bus Protocol Audit

### 5.1 Long Divider Stalls
- When a DIV stalls EX for 32 wait cycles, an instruction fetch already requested on the bus completes on cycle 1.
- `if_buf` latches this prefetched instruction and asserts `if_buf_valid = 1'b1`.
- Because `launch_if` requires `!m_stalling && !if_buf_valid`, instruction fetch requests are suppressed for all remaining stall cycles.
- The system bus remains quiescent in `ST_IDLE`, issuing 0 bus transactions during the stall.
- Verified in `tb_rv32m_pipeline.v`: A concurrent monitor verified that `if_buf_valid` never dropped across all 9 divider stalls, and no spurious fetches were issued.

### 5.2 Back-to-Back M Instructions & Memory Backpressure
- When `DIV` completes, `if_buf` is consumed, clearing `if_buf_valid`.
- The subsequent instruction entering EX immediately asserts `m_stalling = 1'b1`, suppressing `launch_if` from cycle 1. The bus remains safely in `ST_IDLE`.
- Under memory backpressure (`DMEM_DELAY_CYCLES = 3`), all 31 assertions passed with 100% equivalence (simulation time 3976 ns vs 3896 ns).

## 7. Clock Topology & Static Timing Analysis (STA) Closure

### 7.1 Clock Architecture
- **Primary Oscillator Clock (`clk`):**
  - Frequency: 100.000 MHz (Period: 10.000 ns).
  - Port Pin: `E3` (Nexys A7 100 MHz board oscillator).
  - Driven into on-chip `BUFG` primitive (`clk_IBUF_BUFG_inst`).
- **Divided CPU / System Bus Clock (`slow_clk`):**
  - Origin: Flip-flop `slow_clk_reg` in `top_fpga.v` driven by 26-bit counter `clk_cnt`.
  - Toggle threshold: `clk_cnt == 26'd49_999_999` (toggles every 50,000,000 board cycles).
  - Full Clock Period: $100,000,000 \times 10.0\text{ ns} = 1.000\text{ s}$ (1.000 Hz).
  - Driven into dedicated clock buffer `BUFG` (`slow_clk_reg_n_0_BUFG_inst`).
  - Fanout: 2,150 registers (entire `cpu_core`, `sys_bus_interconnect`, `imem_slave`, `dmem_slave`).

### 7.2 Timing Constraints Applied in `constraints/nexys_a7.xdc`
```tcl
################ CLOCK ################
set_property PACKAGE_PIN E3 [get_ports clk]
set_property IOSTANDARD LVCMOS33 [get_ports clk]
create_clock -period 10.000 [get_ports clk]

# Generated clock for the 1 Hz CPU/system bus clock domain (100 MHz / 100,000,000 = 1 Hz)
create_generated_clock -name slow_clk -source [get_pins slow_clk_reg/C] -divide_by 100000000 [get_pins slow_clk_reg/Q]

# Break the internal divider toggle feedback false path (clock generation circuit)
set_false_path -from [get_cells slow_clk_reg] -to [get_cells slow_clk_reg]
```

### 7.3 Timing Closure Verification Results (`docs/core_synth_timing.rpt`)
- **Unconstrained Paths:** **0** (down from 10,184).
- **Unconstrained Register Clock Pins:** **0** (down from 2,150).
- **Total Constrained Endpoints:** **8,597**.
- **100 MHz Clock Domain (`clk`):**
  - Setup Slack (WNS): **+5.959 ns** (Requirement: 10.000 ns, Data Path Delay: 3.905 ns).
  - Hold Slack (WHS): **+0.140 ns**.
  - Failing Endpoints: **0 / 47**.
- **1 Hz CPU Clock Domain (`slow_clk`):**
  - Setup Slack (WNS): **+1,000,000,000.000 ns** (Requirement: 1.0 s, Data Path Delay: 6.538 ns).
  - Hold Slack (WHS): **+0.137 ns**.
  - Failing Endpoints: **0 / 8,550**.
- **Inter-Clock Paths:** **0 failing endpoints**.
- **Pulse Width Slack:** **+4.500 ns** (0 failing endpoints).
- **Status:** **ALL USER SPECIFIED TIMING CONSTRAINTS ARE MET.**

### 7.4 CPU Fmax Assessment
Although the hardware divider runs at 1 Hz for visual display on the Nexys A7 LEDs, STA reveals that the worst-case internal data path delay across all 8,550 endpoints in the CPU (forwarding logic through memory addressing into `RAMS64E`) is **6.538 ns** (6 logic levels). At 100 MHz (10.0 ns period), this path would achieve ~3.0 ns of setup slack.

## 9. Remaining Limitations and Unresolved Risks

1. **Board Clock Domain Crossing to 7-Segment Display:**
   - In `top_fpga.v`, `pc_out` is produced in the 1 Hz `slow_clk` domain and read combinationally by `seven_seg_driver seg_u`, which uses the 100 MHz `clk` for display multiplexing. Because `pc_out` updates once per second, display jitter is non-existent, but a 2-stage synchronizer would be standard practice if `slow_clk` were run at higher frequencies.
2. **Physical Bitstream Generation:**
   - Vivado synthesis and static timing analysis are fully verified. Physical place-and-route (`place_design`, `route_design`) and bitstream generation (`write_bitstream`) were not run in this audit, as the project flow currently standardizes on synthesized STA and unit/pipeline simulations.
